Pinned revision: `3d15126fb1ef74867fc1434be1942e837932691f`.

Underlying Westminster Leningrad Codex (WLC) text: public domain.
The upstream license is retained in `LICENSE.md`. These compact JSON assets are

the existing Open Scriptures Strong's dictionaries or English Strong's tags.

## Rebuilding

Run `python3 scripts/import-oshb.py` from the repository root. It downloads the
commit-specific archive, verifies its SHA-256, parses it using Python's standard
library and builds all 39 per-book JSON assets. Alternatively, download the archive
URL recorded in `manifest.json` and pass its local path as the script argument.
`--output /path/to/output` permits a reproducibility check without modifying assets.
The importer validates all books before writing. No full XML is used at runtime.

## Schema 1

Each book contains `schema`, `revision`, `book`, and `verses`. Verse keys are
English/KJV-style `chapter:verse`. Each verse retains its source OSIS `ref`, a
`words` array, and an optional `variant: true` flag. Word rows contain:

`[OSHB id, original surface, Strong's codes[], raw lemma, morphology, optional variant]`

The original surface preserves vowel points, accents, slash segmentation and
Unicode ordering. Text nested inside `<seg>` is included (including enlarged
letters). Display removes slashes, cantillation and meteg only; vowel points stay.
The normalized dictionary codes remove prefixes, homonym letters and the OSHB
`+` marker, while the raw lemma remains available. Hebrew (`H`) morphology only
is imported; Aramaic is not presented as Hebrew. Standalone tokens with no numeric
Strong's key are omitted. Stable IDs and `ketiv`/`qere` labels are preserved.

## Versification and conservative matching

`wlc/VerseMap.xml` from the same revision supplies whole-verse mappings to English
numbering. Partial boundaries and many-to-one mappings are omitted rather than
guessed. Superscriptions colliding with explicitly mapped Psalm bodies are omitted.
The manifest lists omitted source references. This is not a universal translation
alignment or a claim that BSB and WLC have identical textual traditions.

The app captures reference and version from the rendered verse, and counts the
existing English Strong's entries. BSB/KJV get a unique-match presentation only
when there is one corresponding English entry, one Hebrew occurrence, and no
variant in that source verse. This is a conservative lemma join, not a separately
curated interlinear alignment. Repeated lemmas and variants show all matches with
an explicit verse-level warning. WEB/ASV always use the verse-level presentation;
their existing tags have not been repaired or certified. Missing data, unknown
versification, combined verse ranges, sample-only tags, and failed requests retain
the dictionary popup. Greek cards/search behavior are unchanged.

Per-book JSON is fetched on the first Hebrew popup in that book and cached for
the page lifetime. Failed requests may retry on a later click; stale responses
cannot reopen or replace a different popup. Asset URLs include source and app
versions. The existing mobile build copies these assets automatically.

## Grammar and transliteration

`assets/hebrew-occurrences.js` decodes Hebrew morphology according to the pinned
`parsing/HebrewMorphologyCodes.html`. It preserves person, gender, number, state,
verb stem/conjugation and prefix/suffix components. Unknown grammar is described
as unavailable rather than guessed. Regression tests decode every imported code.

No reliable Hebrew surface-form transliteration utility exists in this repository,
and morphhb does not supply per-occurrence transliteration. This phase therefore
does not generate it. Strong's lexical transliteration and pronunciation remain
in the dictionary section. Adding verse transliteration requires a separately
validated, general Hebrew transliterator and a documented scheme, including
shewa, dagesh, vowel letters, qere/ketiv and divine-name reading conventions.
